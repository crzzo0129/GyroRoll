先懂直觉，再看数学

一个转向电机，怎么同时转弯和扶正？

这是一辆只有一个接地轮的机器人。它没有“扶住左右倾斜”的专用电机。前进时，它通过转向改变轮子与地面的作用，借地面的横向反力把自己扶正。LQR 是决定此刻该转多少、朝哪边转的计算方法。

先记住一句话：像用手指顶着一根竖起来的扫帚，扫帚向一边倒，就要让下面的支撑点及时跟过去。这个机器人不能直接横着推机身；它要先向前走，再用转向和轮地接触实现这件事。
① 横滚动力学② 速度/俯仰环③ 线性化 A、B④ 积分增广与 Riccati⑤ 结果与边界

先看一次真实受力

如果你推它一下，车身先倾、运动方向也会偏。控制器每隔 2 毫秒观察一次姿态和运动，再改变转向电机的力矩，让行进中的轮地反力参与扶正。

五个质量/摩擦随机种子均未跌倒；但把受力瞬间的偏航误差也严格考核时，只有 3/5 通过。它能恢复横滚，不等于能自动回到原来的路线。

1 个接地轮轮子转动负责向前跑；只有轮胎与地面接触。
1 个转向电机同时影响左右倾斜和朝向；没有额外的横滚电机。
必须运动这套控制器从 0.8 m/s 初速起步，不是零速站立方案。

第一步：为什么会倒，转向为什么有用？

  1. 为什么会倒：重心很高，接地点很窄。车身稍向右倾，重力就会继续把它往右拉。
  2. 转向做了什么：电机转的是轮子相对机身的方向，并不是直接掰正机身。车在前进时，轮地接触会产生横向作用力，方向改变也带来偏航。
  3. 怎么扶正：地面作用力发生在重心下方，所以它有使机身横滚的力臂。控制器选取合适的转向，让这个作用与重力造成的倾倒趋势对抗。

转向轴的位置固定在轮轴后方约 0.145 m（负拖距）；控制过程中改变的是转向角和转向力矩，绝不是移动转向轴。这个负拖距几何是当前验收构型，不是最初的正拖距模型。

为了谈清左右：机器人朝前是 +x，左边是 +y，向上是 +z。此页把“向右倾”记作横滚角 φ>0，把“向左转”记作偏航速度 r>0。向左转弯时，正常的稳态身体应向左倾一点；这不是快摔倒，而是在抵消转弯所需的侧向力。

从受力写出横滚方程

设接地点比重心低 h，质量为 m，横滚角为 φ，绕前进方向的惯量为 Iroll。小角度时，接地点相对重心的位置可近似写为 r接触/重心≈(0,hφ,−h)。地面对轮子的力是 F≈(0,Fy,N)，其中 N≈mg。沿 x 轴的力矩由叉乘 τ=r×F 得到：

接触力矩 = 重力引发的倾倒趋势 + 横向反力产生的力矩
τx = ryN − rzFy ≈ hφN + hFyIrollφ̈ ≈ mghφ + hFy

φ>0 表示向右倒。此时第一项为正、会越倒越快；需要足够的右向轮地反力 Fy<0 来抵消。电机没有直接输出横滚力矩，它只能通过转向改变轮地反力。

若以近似恒速 vx 转弯，且轮胎不严重侧滑，侧向向心力约为 Fy≈mvxr。令稳态的 φ̈=0，得出：

0 ≈ mghφeq + mhvxrφeq ≈ −vxr / g向左转 r>0，所以身体应向左倾 φeq<0；这解释了上方滑杆示意。

这只是受力与稳态方向的推导，不是完整机器人方程。实际 Fy 取决于转向角、速度、轮胎接触和负拖距；单轮不能直接照搬自行车的“转角 → 曲率”公式。下面用 MuJoCo 对这些耦合进行局部辨识。

第三步：怎么知道转一点会发生什么？

我们没有假装只用一个扫帚公式就能描述轮胎、负拖距和三维运动。实际做法像轻轻试探，再记账：

  1. 把当前机器人调到约 2 m/s 的行进状态，驱动轮的速度/俯仰反馈继续工作；记录此时的六个侧向状态。
  2. 分别给每个状态一点点正扰动、负扰动，比较 20 ms 之后的状态差；得到矩阵 A，表示状态之间怎样互相影响。
  3. 给转向电机一点点正输入、负输入，再比较 20 ms 后的差；得到单列矩阵 B，表示这个电机能怎样改变六个状态。
  4. 在这个局部模型上算“可控秩”：结果为 6。意思是在约 2 m/s 的局部模型里，单个转向输入经多步耦合能够影响这六个状态；绝不意味着零速或所有姿态都稳定。
记录的量人话解释为什么要看
φ：横滚角现在往哪边斜直接判断会不会倒
φ̇：横滚角速度正在越倒越快，还是正在扶回来不能只看当前倾角
vy：机身侧向速度有没有横向滑走防止只顾转向、实际侧滑
r：偏航角速度现在每秒转多少跟踪手柄左右指令
δ：转向角轮子相对车身朝向哪里防止转向过大
δ̇：转向角速度转向还在往哪边加速抑制来回猛摆

把仿真当作一个可测量的函数

令 x=[φ, φ̇, vy, r, δ, δ̇]ᵀ，u 是归一化转向电机指令。记 FT(x,u) 为在驱动轮闭环工作、转向指令保持不变时，经过 T=0.02 s 后观测到的六维状态。程序先以 0.8 m/s 起步、目标 2 m/s 行驶 4.8 s，取此时状态 x0 和 u0=0 作为工作点。

正负各碰一下：斜率就是局部雅可比
A:,i ≈ [FT(x0+εei,0) − FT(x0−εei,0)]/(2ε)B ≈ [FT(x0,+ε) − FT(x0,−ε)]/(2ε)ε=10−4；代码逐一扰动对应的姿态/广义速度/关节变量，因此 x±εei 是观测坐标中的局部记号。

这是“微分≈两次试验的输出差/输入差”。六个 A 列分别回答六个状态自身被推一点会怎样；单列 B 回答转向电机被推一点会怎样。每次 20 ms 测量包含 10 个 2 ms 的 MuJoCo 步。

xk+1 ≈ FT(x0,0) + A(xk−x0) + Bukξk+1 ≈ Aξk + Buk + d,　ξ=x−x0d=FT(x0,0)−x0：不是严格稳态就不能悄悄删掉这项。

本次辨识的前进速度约 1.996 m/s，工作点偏航速度约 −0.134 rad/s。所以它是行进轨迹上的局部模型，不是数学上精确直行的平衡点。LQR 求增益时忽略常值残差 d，并以有界积分和反馈处理实际偏差；这一点会限制前馈的精确度。

𝒞 = [B, AB, A²B, A³B, A⁴B, A⁵B],　rank(𝒞)=6一个输入不等于只能改变一个状态：多步演化后，转向、横滚、侧向速度与偏航通过耦合互相传递。

可控秩只说明这个线性近似在约 2 m/s 处具有局部可控性，不是大范围非线性稳定性证明；实际回放每 2 ms 重算控制，而此处 A、B 对应 20 ms。

第四步：LQR 如何选转向力度？

给控制器一张“扣分表”：倾倒扣得最重，侧滑、偏航误差、转向过猛也要扣分。控制器计算一组增益 K，让长期预计扣分尽量小。这个求解叫离散 LQR；它解 Riccati 方程，而不是 PPO 训练神经网络。

优先站稳横滚角权重约 386；越倾斜，越急于纠正。
仍要按指令转弯偏航速度、侧向速度和积分误差一起计入。
别把电机打满转向力度也有代价，最终命令限在 −1 到 +1。

4.1 加一个“记住没转够”的状态

只看瞬时偏航误差，受模型偏差影响，长时间可能总差一点。定义积分状态 I 为“目标偏航速度减实际偏航速度”逐步累积。为求增益，先考虑一个固定目标 rcmd，忽略限幅，把六维偏差 ξ 和这个记忆合成 z=[ξᵀ,I]ᵀ。

Ik+1 = Ik + T(rcmd − rk),　T=0.02 szk+1 ≈ Āzk + B̄Δuk + 目标/偏置项Ā = [ A　0 ; −T erᵀ　1 ],　B̄ = [ B ; 0 ],　er=[0,0,0,1,0,0]ᵀ把第 4 个状态 r 的系数变为 −T，是因为实际转得越快，“还没转够”的记忆增长越少。

代码求 K 时使用上式的齐次部分 zk+1=Āzk+B̄Δuk，参考目标及非平衡残差属于仿射项。Δu 是相对参考转向输入的修正；实际实现最后还有前馈、平滑和限幅。

4.2 把“好控制”写成一道最小化题

J = Σk=0…∞ [ zkᵀQzk + R(Δuk)² ]Q = diag(385.966, 2, 37.250, 6.589, 2, 0.2, 4.322),　R=3.671七项依次处罚横滚角、横滚速度、侧向速度、偏航速度、转向角、转向角速度、偏航积分；R 处罚电机修正力度。

把未来每一步的扣分相加，越早纠正倾倒越划算，但猛打电机也要付代价。Q、R 是本项目仿真调出的设计权重，不是用质量与重力直接算出的自然常数；状态的单位不同，不能单看数字大小解释真实物理量的绝对重要性。

4.3 从 Bellman 方程推到 K

猜测从当前状态出发的最小未来代价是二次型 V(z)=zᵀPz。把“本步扣分 + 下一步最小代价”展开，并对当前电机修正量 Δu 求导令其为零：

V(z) = minΔu { zᵀQz + R(Δu)² + (Āz+B̄Δu)ᵀP(Āz+B̄Δu) }0 = (R+B̄ᵀPB̄)Δu + B̄ᵀPĀzΔu* = −Kz,　K = (R+B̄ᵀPB̄)⁻¹B̄ᵀPĀ导数中的公共因子 2 已约去；这里 R 是一个标量，K 是 1×7 行向量。

把最优的 Δu* 再代回去，就得到离散代数 Riccati 方程（DARE）。求出满足稳定条件的 P，再代入上面的 K 式：

P = Q + ĀᵀPĀ − ĀᵀPB̄(R+B̄ᵀPB̄)⁻¹B̄ᵀPĀK ≈ [0.92254, 0.02022, −0.52983, 0.01040, 1.26286, 0.05606, 0.07551]

这个 K 就是代码用 solve_discrete_are 求得的增益。理想的 20 ms 增广线性模型中，开环 Ā 的最大特征值模约 1.00256，闭环 Ā−B̄K 约 0.99164（小于 1），表示该局部线性、未限幅的离散近似收敛；它不构成 2 ms 实际非线性回放的全局稳定性证明。

4.4 从 K 到真正在执行的力矩

转弯时不能总把目标设成直立，否则要转弯和要扶正会一直打架。用近似定常关系 ξk+1=ξk，暂时忽略前面说过的残差 d，算持续转向输入对应的六维状态变化：

ξ = Aξ + Bu　⇒　G = (I6−A)⁻¹B,　ξ ≈ GuG ≈ [2.47510, 0.11097, 15.54951, −25.57572, 7.74587, −0.18262]ᵀGr=−25.57572 是第 4 项。负号是此模型转向电机方向及耦合的结果，不应凭“向左转”直觉擅自改号。

假如希望偏航速度改变 rf，粗略地取 uff=rf/Gr；程序还乘上调参系数 1.15，生成六维参考状态 xref。然后用刚算出的 K 修正参考与实测的偏差：

rf ← rf + Δt(rcmd−rf)/(0.125+Δt)I ← clip(I+Δt(rf−r), −0.078695, 0.078695)uff = 1.15rf/Gr,　xref = x0+Guffusteer = clip(uff−K1:6(x−xref)−K7I, −1, 1)τsteer = 2.4usteer N·m实际仿真 Δt=0.002 s；K1:6 是前六个反馈系数，K7 是积分项系数。

一句话读法：预备转向 − 六维状态反馈 − 没转够的累计修正，最后限幅。尤其要注意，xref 是局部模型推算的近似参考，工作点本身偏航约 −0.134 rad/s、并非精确直行，所以这个前馈并不保证指定转弯半径；积分修正也有边界。

辨识时俯仰目标的限幅为 ±0.3 rad，运行时驱动环为 ±0.6 rad；在局部微小扰动附近通常都不触发，但大动作不能用此线性推导直接外推。实际系统也包含速度目标斜坡、命令滤波、饱和与轮地非线性。

第五步：它确实做到什么，还没做到什么？

缓丘直行测试在五个质量/摩擦随机种子中 5/5 通过；1 N、0.2 s 机身侧向力实验五个种子均未跌倒，但严格偏航综合阈值为 3/5。这些数字证明的是指定仿真条件，不是任意地形与冲击。

更重要的是：它的状态里没有世界坐标 y 位置，也没有绝对航向角目标。外力之后横滚和偏航速度恢复，并不自动驶回原路线。

零速不保证平衡

控制器依赖行进中的转向—轮地接触耦合；测试从非零前进速度起步。

只在局部设计

增益来自约 2 m/s 的理想状态模型；高速猛打方向、坡上强外力组合未通过普适验收。

不是强化学习成果

这三段主演示加载的是 LQR。项目确实训练过 PPO，但该策略没有取得这里的主验收结果。

还不是实物证明

没有传感噪声、转向机构柔度、轮胎形变、执行器延迟和温升模型。
