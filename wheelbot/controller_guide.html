飞轮独轮车的控制器设计

这里说的是 wheelbot，不是带竖直转向关节的 steerbot。下轮负责前进与前后平衡，上飞轮负责左右平衡；偏航来自飞轮、姿态运动和轮地接触的耦合，没有独立偏航电机。

明确结论当前验收和下面的手柄仿真用 --controller thin：不是 PPO，也不是 LQR。它是七个主要增益加起步、限速和回正逻辑组成的显式状态反馈，参数在 MuJoCo 轨迹上优化。--checkpoint 才切换到 PPO 网络回放；本项目没有为 wheelbot 定义 LQR 控制器。

01 · 两台电机分别能做什么

坐标机身 +x 前方、+y 左方、+z 上方。
主轮绕局部 y 轴，半径 0.12 m、半宽 0.004 m；电机最大约 2.4 N·m。
上飞轮绕局部 x 轴，半径 0.083 m、质量 0.44 kg；电机最大约 2.4 N·m。
初始条件飞轮预旋 100 rad/s；此值是仿真重置时直接设定的。
控制周期物理步长 0.002 s；显式反馈每步计算一次，约 500 Hz。

从正面看，机身像一个倒立摆。前后倾时，下轮移动接地点，把支撑点带到重心附近；左右倾时，上飞轮电机加速转子，机身受到绕 x 轴的反向反作用力矩。因此飞轮可以直接帮助横滚平衡，却不能像方向盘一样直接指定绕 z 轴的偏航力矩。

飞轮沿 x 轴转动时有角动量 H ≈ JR ΩR ex。如果机身同时俯仰，飞轮轴方向改变，dH/dt 中会出现 ω × H 项，其偏航力矩量级约为 JR|ΩRq|。但车轮滚动、横滚、机身惯性与轮地接触也参与偏航；这个项存在不等于它在当前轨迹中占主导。

被控对象内部的交叉通道（不是控制器中的显式乘法）：
来自上行的俯仰速度 q + 来自下行的飞轮速度 ΩR → 陀螺耦合；横滚 φ + 轮胎运动 → 轮地接触力与其他惯性耦合。它们共同影响机身偏航角速度 r。不能仅从控制律判断每一项占比。
反馈闭环：vx → 速度误差与转弯低速门控；θ、q → 俯仰 PD；φ、p、ΩR → 飞轮反馈；r → 横滚参考 φref。对用户直接追踪的输出是前进速度 vx 与偏航角速度 r；姿态和飞轮速度是内部状态。

这条现有控制器没有 rcmd → θref、没有“命令 q”的偏航通道，也没有转弯时锁定 ΩR 的速度环。俯仰速度由前进平衡环、指令变化和接触扰动产生；飞轮转速由历史电机力矩演化。这正是它与显式设计陀螺转向轨迹的非线性控制器不同的地方。

03 · 前进：速度外环与俯仰内环

以下是这份 验收参数在 ThinWheelController 中的实际计算。Δt=0.002 s，vx 为机身坐标系前向速度，q 为绕 y 轴的机身俯仰角速度；clip(x,a,b) 表示把数值限制在 [a,b]。

前 2 s：vcmd,used = min(vcmd, 1.0 m/s)
vtarget,k+1 = vtarget,k + clip(vcmd,used − vtarget,k, −2.5Δt, 2.5Δt)
θref = clip[0.100836(vtarget − vx), −0.3, 0.3]
uD = clip[9.897686(θ − θref) + 2.403866q, −1, 1]uD 为归一化下轮电机命令；绝对值 1 对应模型中的约 2.4 N·m 关节力矩。

物理直觉：目标速度比实际速度高，就要求一个相应的俯仰参考；下轮既要防止倒下，也要让车逐渐达到目标速度。角速度项相当于抑制俯仰摆动。系数不是从一个通用倒立摆解析式直接推出来的，而是为当前构型在仿真中调出来的。

04 · 转弯：偏航误差变为横滚目标

记手柄转弯输入为 rcmd，实测偏航角速度为 r。低速时先将转弯命令衰减：速度低于 1.1 m/s 时为 0，达到 1.8 m/s 时才是全量。

g(vx) = clip[(vx − 1.1)/(1.8 − 1.1), 0, 1],　rc = g(vx)rcmd
φref = clip[−0.203837rc + 0.011617(rc − r), −0.4, 0.4]
uR,base = clip[3.631801(φ − φref) + 1.150946p + 0.0005ΩR, −1, 1]p 为横滚角速度，ΩR 为飞轮相对机身转速；0.0005 = 0.0012 / 2.4，是按模型阻尼与电机力矩写的补偿。

为什么飞轮转速前面是正号？

模型里飞轮关节的黏性阻尼总是反对当前转动：飞轮正转时阻尼为负力矩，反转时阻尼为正力矩。电机模型则以 2.4uR N·m 对飞轮施力。因此控制器用同号电机力矩抵消阻尼：

τmotor = 2.4uR,　τdamping = −0.0012ΩR
ufriction = (0.0012/2.4)ΩR = 0.0005ΩR

例如 ΩR=100 rad/s、姿态误差和角速度项暂为零时，命令 uR=0.05，电机作用 +0.12 N·m，关节阻尼 −0.12 N·m，两项相消。它的符号看起来像“速度越大、越给正命令”，但在这个理想模型下只是阻尼前馈抵消，不是把速度误差放大的正反馈控制。它也不提供速度收敛：忽略其他耦合时，飞轮近似满足 JRΩ̇R ≈ 2.4ubalance。因此飞轮转速可以累积漂移、饱和；真实阻尼不准时还可能欠补偿或过补偿。

举个量级例子。 前进约 2 m/s、要求左转 +0.35 rad/s，偏航误差很小时，横滚目标约 −0.071 rad，即向左倾约 4.1°。协调转弯的量级 |φ| ≈ v|r|/g 恰好也约为 0.071 rad；数值接近并不能证明该机器依靠“自行车式倾斜转向”，也不能证明陀螺项是主因。它只是帮助理解这个参考角的大小，代码没有实时计算此式。

你指出的俯仰–飞轮耦合究竟在哪里？

用局部机身坐标作简化：飞轮角动量主要沿 +x，机身以 q=θ̇ 绕 +y 俯仰，则 (q ey) × (JRΩR ex) = −JRΩRq ez 是改变飞轮角动量所需的陀螺力矩，机身受相反作用。实际运动可以概括成：

Iz·ṙ ≈ JRΩRq + τcontact,z + 其他惯性/约束项教学性分解，不是此 MuJoCo 模型的完整偏航方程；各项大小与符号依赖实际姿态、接触和坐标。

然而 ThinWheelController.act() 中 rcmd 只进入 φref，没有进入 θref 或一条单独的俯仰摆动轨迹。所以上述乘积是物理被控对象内发生的效应，不是控制器明确规定“转左时让 q 和 ΩR 取什么值”。偏航误差通过横滚目标间接改变飞轮力矩；下轮继续按速度和平衡需要驱动俯仰。当前回放能跟踪偏航，但仅凭这段代码和 RMSE 不能断言陀螺项与接触项各占多少，更不能把它等同于显式陀螺偏航 MPC。

“俯仰角为零”与“俯仰速度为零”是两回事。机身刚经过 θ=0 时仍可能有 q=θ̇≠0，陀螺项不会因此消失。如果 θ 在一段时间严格恒为 0，则 q=0，上式的 ΩRq 项确实为零。此时是否还有偏航，必须看完整的轮地接触和其他耦合，不能由这一个项推出“绝对无法转向”；反过来，也不能因此宣称现有控制器能在俯仰锁死后正常转弯。

当前测试没有锁住俯仰。下轮速度误差常使 θref 非零；正常行驶中姿态和接触也会持续扰动 q。在一条不加随机化/冲击的名义 15 s 回放中，t=6 s 记录为 θ≈0.0145 rad、q≈−0.0192 rad/s、ΩR≈+99 rad/s、r≈+0.331 rad/s；t=10 s 为 θ≈0.0074 rad、q≈−0.0116 rad/s、ΩR≈−130 rad/s、r≈−0.343 rad/s。这证明该回放并非 θ=q=0；左右转时飞轮转速与偏航速度各自变号，也不能单独证明陀螺项占主导。力矩对应角加速度，不能直接从角速度符号反推。

此外，若 θ 保持非零但 q=0，上式的旋转角动量项暂时没有了；不过机身倾斜会使绕机身 x 轴的电机反力矩在世界竖直方向出现约 τRsinθ 的投影，轮地接触也可能提供偏航力矩。具体加速度仍须使用完整动力学计算。

如果要显式设计陀螺转向：需要让偏航外环依据当前 ΩR、俯仰状态和轮地约束，规划下轮与飞轮两台电机的联合动作，使期望的 q·ΩR 耦合在保持平衡、速度和力矩限制下出现。这是另一种待实现的控制架构，不是将现有 φref 公式改个名字。Mini Wheelbot 论文 使用非线性 MPC / 近似 MPC 探索这种偏航控制；论文硬件与本仓库概念模型的几何和参数并不相同。

05 · 为什么要预旋、如何回正

启动仿真时，代码把飞轮关节初速度直接设成 100 rad/s，因此一开始就有非零角动量。这是验收初始条件，不是控制器已证明能从静止飞轮自行起旋到该状态；也不能据此断言“没有这 100 rad/s 就一定不会转弯”。运行中 ΩR 还会随电机力矩变化。

当有效转弯指令绝对值大于 0.02，控制器置位 has_turned，并清空回正积分。转弯结束后（指令小于阈值），积分实测偏航角速度并在 ±1 截断：

Ik+1 = clip(Ik + Δt·rk, −1, 1)
uR = clip[uR,base + 0.3r − 0.02I, −1, 1]按当前 JSON：recovery_rotor_gain = 0，recovery_yaw_gain = −0.3，recovery_yaw_integral_gain = 0.02。正负号是代入原始代码后的结果。

这个修正旨在让转向指令归零后偏航角速度回落。由于飞轮不是直接的偏航电机，不能凭“+0.3r”单项的符号判断它会直接加速还是制动偏航。当前默认的转弯前偏航/飞轮转速附加增益均为 0；回正项也不保证飞轮转速回到 100 rad/s。回正表示停止转动，不表示返回原航向或原路径。

06 · 控制器从哪里来；PPO、LQR各在哪里

运行方式动作如何产生这份验收/手柄命令在用？
wheelbot --controller thin上述速度、俯仰、横滚、偏航状态反馈；七个主要系数在 MuJoCo 轨迹上优化，另有起步/回正参数是
wheelbot --checkpoint ...PPO 策略网络从观测预测两个电机动作；仿真分支每 10 个物理步更新动作否，只有明确传 checkpoint 才走网络
wheelbot --controller lqr仓库没有为 wheelbot 实现 LQR；sim.py 会拒绝这个组合不能使用
wheelbot（未指定控制器）早期直行平衡 baseline；不按转弯指令闭环跟踪偏航否

thin 的七个主要系数最初由 optimize_wheel_rounded.py 的差分进化轨迹评分寻找，后续配置还加入了启动和偏航恢复设置；这是基于仿真调参的显式反馈，不是用 Riccati 方程根据线性模型求得的 LQR，也不是神经网络推理。PPO 的 train.py 与 policy.py 是独立路线，不能把下面的 thin 验收数字说成 PPO 的成绩。

每一步 control.py 的 observe() 从 MuJoCo 真值读姿态、速度与飞轮关节速度，再由 ThinWheelController.act() 算出两个归一化动作。当前不是带有传感器噪声、IMU 融合和硬件通信时延的实机控制软件。

08 · 验收证明了什么，没证明什么

已有固定 15 秒测试按 1 m/s 起步、2 m/s 直线、左右各 3 秒 ±0.35 rad/s 转弯、最后降至 1.5 m/s 回正；在机身质量 ±15%、轮地滑动摩擦 1.1–1.9 和两次侧向/横滚角速度冲击下，种子 0–4 的预定顺序 5/5 通过。该组平均稳态速度 RMSE 约 0.234 m/s，转向偏航 RMSE 约 0.112 rad/s；数值是 thin 的 CPU 仿真回放，绝不是 PPO 或 LQR 的成绩。

不要把 5/5 理解成任意手柄轨迹都安全。预旋 100 rad/s、窄刚性圆柱胎、高飞轮力矩和理想状态观测都是测试条件。持续同向转弯可能令飞轮角动量积累，额外测试曾在约 10–17 秒跌倒；瞬时偏航速度也可能显著超出指令。模型未包含轮胎形变、电机温升、传感噪声与硬件延迟。

原始模型 model.xml 是半宽 16 mm、飞轮电机最大 0.48 N·m 的不同对照构型。这里的控制器与验收结果只对应 validated_model.xml 的半宽 4 mm、飞轮电机最大 2.4 N·m 构型。完整数据和图表见 wheelbot 实验报告。
