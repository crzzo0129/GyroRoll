# 开放轮圈机器人：MJLab 1.3.0 直接强化学习

训练对象是当前 240 mm 开放滚动轮、166 mm 外露飞轮、上方机身的 `wheelbot/nested_model.xml`。训练任务位于 `miniwheelbot_rl/`，与旧的力矩动作训练和传统反馈回放分开。

## 动作和物理含义

策略的两个输出按固定顺序排列：`[飞轮, 滚轮]`。输出归一化后裁剪到 [-1, 1]，分别映射为 [-250, 250] rad/s 和 [-35, 35] rad/s。正负号表示对应 MJCF 关节轴的旋转方向；它不直接等于车辆前进或左转方向，策略需要学习身体运动与轮子旋转的关系。两个输出都是绝对目标轮速，没有固定飞轮速度偏置。

XML 速度伺服在每个物理步计算 `力矩 = clip(kv × (目标轮速 − 当前轮速), −2.4, 2.4)` N·m。飞轮 kv=0.12，滚轮 kv=0.25，传动比为 1。零目标速度会制动；策略不会直接写入 qvel，真实轮速可以因惯性或外部作用短暂超过目标范围。奖励另有超速惩罚。以上是仿真的初始电机参数，可在 `Settings` 中调整，尚不是实测硬件规格。

所核对的 MJLab 1.3.0 安装包已在内置速度执行器中取消范围继承，支持无限旋转关节。本任务使用原生 XML `<velocity>`、明确的目标轮速 `ctrlrange` 和力矩 `forcerange`，由 `XmlActuatorCfg` 包装，便于保存并复现速度伺服的完整参数；无需修改 MJLab 安装包。

## 指令、观测与奖励

指令为 `[前进/后退速度 m/s, 朝向角速度 rad/s]`，横向速度目标固定为零。每 3–6 秒重新采样；10% 环境分配静止指令。转向角速度从机身前向轴在水平面的投影求导计算，在倾斜时也区别于单纯机身 z 轴角速度。

Actor 和 Critic 使用相同的 15 维观测：机身线速度 3、角速度 3、重力投影 3、按飞轮/滚轮顺序归一化的实际轮速 2、指令 2、上一动作 2。不输入连续旋转轮子的无限累积角位置，不调用传统平衡控制器，不使用 MPC 专家或模仿学习。初始轮速为零并加入 ±1 rad/s 小扰动，初始横滚/俯仰加入 ±0.025 rad 扰动。

PPO 从随机策略学习。奖励以站立程度加权的前进速度与转向角速度跟踪为主，同时奖励站稳，惩罚横向滑动、姿态晃动、动作变化、力矩、超速与跌倒。轮速伺服只实现电机速度环，身体平衡和转向均交给策略。

姿态晃动已拆成独立的 `roll` 和 `pitch` 奖励，分别惩罚机身 x、y 轴角速度的平方，当前权重分别为 -0.05 和 -0.01（横滚惩罚提高为原来的 5 倍）。可在 `miniwheelbot_rl/task.py` 的奖励配置中分别调整；TensorBoard 分别显示 `Episode_Reward/roll` 与 `Episode_Reward/pitch`。恢复课程中两项沿用相同的直立门控系数，侧躺时降至各自完整权重的 20%。

新训练策略版本为 `bounded_mean_gaussian_v1`：均值经过 tanh，限制在 [-1, 1]；每个动作维度独立学习标准差，初始 0.1，以 sigmoid 参数化限制在 [0.02, 0.2]；熵系数为 0。训练采样为 `均值 + 标准差 × 高斯噪声`，之后仍执行动作裁剪，确定性回放直接使用 tanh 均值。旧无界策略仅保留原行为回放/评估，新版本须从头开始；新版本 checkpoint 可正常续训。这一步不调整环境奖励和电机参数。

物理步长 2 ms，5 步执行一次策略（100 Hz）。一回合 20 秒；倾斜超过 0.70 rad 或机身参考点高度低于 0.185 m 提前终止。可选 `--randomize` 会改变所有轮圈/胎面摩擦并加入速度冲击。

## 云端安装与运行

按用户要求，PPO 训练在云端进行。上传 `dist/miniwheelbot_mjlab130_cloud.zip`，按照 [云端说明](../CLOUD_README.md) 配置 Linux Python 3.12、CUDA PyTorch，完成环境检查后再正式训练。本地没有启动 PPO。

依赖固定为 MJLab 1.3.0、MuJoCo 3.7.0、MuJoCo-Warp 3.7.0.1、Warp 1.12.0、PyTorch 2.7.1；MJLab 自身固定 RSL-RL 5.0.1。代码启动会检查 MJLab 精确版本和 CUDA 是否可用。纯物理训练不要求桌面窗口，浏览器回放默认使用 Viser。

```bash
python -m miniwheelbot_rl smoke --num-envs 4
python -m miniwheelbot_rl train --stage warmup --num-envs 256 --iterations 3000
```

三个手动阶段的对称指令范围：

| 阶段 | 前进速度范围 m/s | 转向角速度范围 rad/s |
|---|---|---|
| warmup | ±0.5 | ±0.20 |
| tracking | ±1.2 | ±0.40 |
| full | ±2.0 | ±0.60 |

也可直接使用 `--stage full` 从头学习完整范围；分阶段继续训练使用同一两维动作与观测结构，不引入专家动作。将示例路径换成实际训练输出的路径：

```bash
python -m miniwheelbot_rl train --stage tracking --num-envs 256 --iterations 3000 --checkpoint logs/rsl_rl/nested_velocity_mjlab130/RUN/model_XXX.pt
python -m miniwheelbot_rl train --stage full --randomize --num-envs 256 --iterations 5000 --checkpoint logs/rsl_rl/nested_velocity_mjlab130/RUN/model_XXX.pt
python -m miniwheelbot_rl play --num-envs 1 --checkpoint logs/rsl_rl/nested_velocity_mjlab130/RUN/model_XXX.pt
python -m miniwheelbot_rl evaluate --num-envs 8 --duration 15 --checkpoint logs/rsl_rl/nested_velocity_mjlab130/RUN/model_XXX.pt
```

每次训练保存 `task.json`（动作顺序、单位、物理参数、阶段、随机化选项和几何校验值）、`geometry.xml` 几何快照、`agent.json`、TensorBoard 曲线与 checkpoint。回放/评估必须保留 checkpoint 旁的这些文件，自动重建原几何、动作缩放与电机参数。旧力矩动作 checkpoint 不兼容。

云端先用 256 环境测实际显存和吞吐，再决定是否增加。该模型有 192 个环形扇区网格，不能直接套用四足机器人数千并行环境的吞吐预期。已完成四项速度伺服物理测试和四世界 MuJoCo-Warp GPU 步进检查；完整 MJLab 环境、PPO 更新与 Viser 回放仍需按云端说明验证。

## 评估定义

独立评估静止、前进、后退、前进左/右转、后退左/右转七类固定指令；每类默认 15 秒、多个随机初始状态。前三秒为启动阶段，之后计算前进速度、真实朝向角速度和横向速度 RMSE。每个初始状态必须全程不倒，且三个 RMSE 分别小于 0.35 m/s、0.15 rad/s、0.35 m/s 才计通过。跌倒后的自动重置不能让该初始状态重新获得通过资格；没有有效数据的误差写为 null。

这些是名义模型检查，与旧 `accept.py` 的 2 m/s、随机质量和冲击序列不同。阶段范围外的评估指令用于检查泛化，不能要求 warmup 策略已学会 1 m/s。小规模训练能证明数据采样、PPO 更新和保存正常，不能证明速度跟踪已训练成功；必须查看评估结果。
