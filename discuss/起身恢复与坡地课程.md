# 同一个策略：速度跟踪 → 起身 → 摔倒恢复 → 坡地

实现入口：`python -m miniwheelbot_rl`。所有课程共享同一个 actor、同样的 15 维观测和两个轮速动作；从上一阶段 checkpoint 继续训练，最后只部署最后一个 checkpoint。没有起身控制器切换，也不向策略输入阶段编号。

## 课程顺序

| `--stage` | 初始姿态 | 地形 | 外部扰动 | 速度/转向范围 |
|---|---|---|---|---|
| `warmup` | 近直立 | 平地 | 可选 | ±0.5 m/s，±0.2 rad/s |
| `rise_tilt` | 50% 近直立；50% 左右倾斜 20–60° | 平地 | 无 | 同上 |
| `rise` | 40% 近直立；60% 左右倾斜 60–100° | 平地 | 无 | 同上 |
| `recover` | 60% 近直立；40% 倾斜 45–100°，其中 25% 为前后倾并叠加少量侧倾 | 平地 | 每 7–10 s 加一次速度扰动 | 同上 |
| `slope3` | 75% 近直立；25% 左右倾斜 | 平地和 ±1.5°、±3° | 小扰动 | 同上 |
| `slope6` | 70% 近直立；30% 倾斜，包含前后倾 | 平地和 ±3°、±6° | 中等扰动 | ±0.8 m/s，±0.3 rad/s |
| `slope10` | 同上，增加前后倾比例 | 平地和 ±5°、±10° | 较强扰动 | ±1.2 m/s，±0.4 rad/s |
| `mixed` | 60% 近直立；40% 倾斜 20–100°，混合左右/前后 | 平地和 ±5°、±10° | 较强扰动 | 同上 |

坡地阶段每次重置随机选择地块：40% 平地，剩下四个坡度各 15%。随机航向覆盖上坡、下坡、横坡。`--randomize` 另外增加摩擦随机化；`recover` 以后的课程本身已包含扰动。回放和评估关闭随机扰动，评估中的推扰是单独安排的固定测试。

这是需要评估后手动升级的课程，不会训练到某个迭代数就自动增难。建议同阶段多种 seed 下各项验收通过率达到 90% 再继续；这个比例是起始建议，不是已验证的实物标准。10° 是待验证目标；6° 不稳定就继续留在 6°，不要直接上 10°。

## 控制与奖励

- 保留现有身体线速度、角速度、投影重力、两轮转速、速度指令、上一动作，共 15 维。
- 动作仍为飞轮/滚轮的目标角速度，分别 ±250 / ±35 rad/s，力矩上限仍为 2.4 N·m；具体以 checkpoint 保存的设置为准。有界均值策略可直接续训。
- 不隐藏、不清零原始速度指令。起身后同一个策略继续跟踪原指令。
- 新阶段跟踪权重随当前倾角连续变化：超过 60° 时关闭，小于 20° 时全开，中间线性插值。前进/航向跟踪权重仍为 4 / 2。
- 直立奖励改为 `4 × (1 + 机体竖直轴的世界竖直分量) / 2`，在侧躺附近也有区分度。
- 动作变化、力矩和晃动惩罚在躺倒时降至原来的 20%，站稳后恢复原权重；实际电机限幅始终保留。
- 新发生一次摔倒扣 2 分（已抵消奖励管理器的 dt 缩放）。初始躺倒不扣这笔费用。没有可反复领取的起身奖金；持续保持姿态和速度跟踪产生收益。

上述奖励调整仅作用于新课程，原 `warmup/tracking/full` 奖励及终止规则保留。新增阶段不是保证已经学会起身，仍需要云端训练和评估。

## 恢复、重置和地形定义

新阶段取消原来的大倾角/低高度立即终止。倾角超过 0.7 rad 或离地法向高度小于 0.185 m 时开始一次恢复尝试；初始倾斜样本从重置时开始计时。5 s 内必须达到倾角小于 20°、法向高度大于 0.30 m、机体 roll/pitch 角速度合量小于 1.5 rad/s，并连续保持 1 s。短暂竖直不会重置恢复期限。成功后若再次摔倒，开启新一次计时。失效状态、穿地超过 0.1 m 或恢复超时判失败。

恢复计时只用于终止和统计，奖励门控只依赖当前物理状态，不依赖隐藏模式。这保留了旧网络输入兼容性；剩余恢复时间和地形法向没有额外输入给 actor，因此它不是包含全部任务状态的严格 Markov 观测。若复杂地形后续确实需要感知/历史，需要另外版本化观测并处理权重迁移。

重置从实际 XML 提取网格/盒体顶点，圆柱和胶囊用解析支撑距离。轮子初始关节角固定为零，以保证与碰撞支撑几何一致；随机机体倾角、航向和坡度后沿世界竖直方向放置，使最低碰撞点在地面法向上留 2 mm 间隙。不会把直立高度机械地用于侧躺，也不会额外冻结仿真来伪造起身。

坡地为 64 m 地块中央的连续平面，离中心任一水平轴超过 28 m 判边界失败，避免把穿越地块接缝混入本阶段。所有离地判定用局部地面法向距离。前进目标表示“机体前向投影到坡面后，沿该方向的地面切向速度”；横向速度同样在坡面内计算。转向仍表示水平航向的变化率。actor 的原始身体速度观测布局不变。

## 云端执行

更新代码后，使用原来的训练环境。在项目根目录先运行：

```bash
python -m unittest discover -s tests -p 'test_rl_*.py' -v
python -m miniwheelbot_rl smoke --stage rise_tilt --num-envs 4
python -m miniwheelbot_rl smoke --stage slope3 --num-envs 4
```

从当前效果正常的有界策略开始第一阶段。把路径替换为你最近的速度跟踪 checkpoint，保留旁边的 `task.json` 和 `geometry.xml`：

```bash
python -m miniwheelbot_rl train --stage rise_tilt --num-envs 256 --iterations 3000 \
  --checkpoint logs/rsl_rl/bounded_warmup/2026-10-14_08-56-16_warmup/model_499.pt \
  --log-root logs/rsl_rl/recovery_curriculum
```

若已有更晚、效果更好的 checkpoint，应替换上面的 `model_499.pt`。每次运行生成新的目录；下阶段接着加载上一阶段的输出，不要每次都重新加载最初的 warmup 模型。依次将 `--stage` 改成 `rise`、`recover`、`slope3`、`slope6`、`slope10`、`mixed`。`--iterations` 是本次追加的更新次数；3000 是初始安排，不是通过标准。

评估当前阶段（默认会自动选择 curriculum 套件）：

```bash
python -m miniwheelbot_rl evaluate --checkpoint RUN/model_XXX.pt \
  --suite curriculum --num-envs 16 --duration 15 --output results/recovery_evaluation.json
```

也可以显式设置较早的 `--stage rise` 或 `--stage recover`，检查坡地训练后是否遗忘平地起身。`rise_tilt` 测 45° 左右倾斜；`rise` 增加左右侧躺；`recover` 增加前后倒地和推扰；坡地阶段加入各坡度、各行驶方向和坡上起身。评估初始姿态加入由 seed 控制的 roll/pitch ±2°、yaw ±5° 小扰动，避免多个并行环境只是完全相同的确定性副本；视频和诊断的指定姿态不加这些扰动。

验收要求：原始回合未失败、结束时稳定、至少 1.5 s 有效跟踪数据，以及前进/航向/横向 RMSE 分别小于 0.35 m/s、0.15 rad/s、0.35 m/s。初始躺倒必须真正完成恢复。恢复后的跟踪窗口从第 6 s 开始，推扰案例从第 8 s 开始；期间再摔倒也计入误差。失败试验后续即使被重置，也不会再进入成功统计。推扰未导致摔倒会显示 `needed_recovery=false`，不伪称完成了一次起身。

导出左侧躺倒起身视频，下载 MP4 即可观看：

```bash
MUJOCO_GL=egl python -m miniwheelbot_rl video --checkpoint RUN/model_XXX.pt \
  --start-pose left --duration 15 --speed 0.3 --turn 0 \
  --video results/rise_left.mp4
```

`right/front/back` 分别测试另一侧及前后倒地；`tilt_left/tilt_right` 是 45°。视频/诊断默认从直立开始，`--start-pose random` 可随机采样本课程。坡地回放可加 `--terrain-column 3 --heading-deg 0`；列 0 是平地、1/2 是正负半坡、3/4 是正负满坡。满正坡下航向 0/180/90 分别为上坡/下坡/横坡。

离线诊断 HTML 现在还显示倾角、离地高度、恢复状态与累计成功次数：

```bash
python -m miniwheelbot_rl diagnose --checkpoint RUN/model_XXX.pt \
  --start-pose left --duration 15 --speed 0.3 --diagnostic-dir results/rise_diagnostic
```

TensorBoard：

```bash
tensorboard --logdir logs/rsl_rl/recovery_curriculum --host 0.0.0.0 --port 6006
```

优先看 `Episode_Metrics/recovery/attempts`、`successes`、`success_fraction`、`mean_recovery_seconds`，以及 `resumed_forward_rmse`、`resumed_yaw_rmse`、`resumed_count`。没有恢复/没有恢复后样本时相关数值记为零，必须结合次数阅读；success_fraction 是各回合比例的平均，不能直接当作全局尝试加权成功率。`tracking/forward_mae` 和 `tracking/yaw_mae` 是包含起身过程的真实时间平均绝对误差，区别于默认 command manager 的累积误差。正式验收使用 JSON 中分场景数据。

## 版本和验证范围

新训练记录 `task_version=recovery_slopes_v1`、课程参数、观测合同及原几何/电机设置。有界策略的旧 checkpoint 可以续训，旧无界策略仍仅支持回放。训练不改变动作顺序、网络尺寸或既有检查点文件。

本地 CPU 回归涵盖恢复期限、连续稳定、二次跌倒、部分环境重置、失败试验统计隔离，以及 84 组姿态与坡度的真实 MuJoCo 接触检查。最终机器人学习效果、MJLab GPU 训练吞吐和坡度能力，需要运行上述云端 smoke、短训练与评估确认。
